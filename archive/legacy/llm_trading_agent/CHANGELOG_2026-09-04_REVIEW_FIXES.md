## 已修改

### 1. `order_executor.py`

- 修复空仓期资金费率被补算到下一笔仓位的问题：新开仓重新建立 funding 时间锚，全部平仓/强平后清空锚点。
- funding 改为按结算时点 `abs(qty * price)` 的仓位市值计算，并允许负费率；统计字段按“正数=净支付、负数=净收取”解释。
- 全平手续费改为按退出价的实际退出名义额计算。
- 修复 `save_state(price=None)` 且空仓时再次叠加 `realized_pnl` 的错误；此时权益直接等于 cash。
- 持久化 funding 锚、next-open 待办、bar counter、最近离场和 live 最后处理K线，避免重启丢失关键状态。
- 防止 next-open 模式同一根K线重复调用止损/移动止盈检查时重复增加触发统计。
- 新增 v10 的 RL1、冷却吞 BUY、RL2 降杠杆三个独立统计字段。
- 账户级回撤闸门提示改为“永久停机，需要人工审查后复位”，不再宣称空仓后能自动创新高恢复。

### 2. `config.py`

- `EQUITY_DRAWDOWN_LIMIT_PERCENT` 默认值从 25% 调整为 15%，与项目文档中的账户回撤预算一致。
- 明确该账户闸门是 kill switch，而不是自动恢复型熔断。

### 3. `data_fetcher.py`

- 新增 `closed_klines_only()`，按 `open_time + interval` 判断K线是否已经闭合。
- 补齐 30m、2h、6h、8h、12h、3d、1w 等周期长度。
- 未识别周期会明确报错，不再静默使用可能未闭合的数据。

### 4. `main.py`

- live 和回测在计算指标前过滤尚未闭合的K线。
- live 记录并检查 `last_processed_bar`，程序重启或重复调度时不再对同一闭合K线重复调用 LLM/下单。
- live 信号只来自完整K线；成交改用调用时可执行的最新价格。若最新价不可用，本轮 HOLD，不再按过去的收盘价虚拟成交。
- 可复现指纹增加完整 OHLCV 序列 SHA-256，同时保留原尾50收盘 SHA-1。
- 报告把“交易次数”拆成“成交动作、平仓回合、期末是否持仓”。
- 资金费率报告明确为净成本，并显示正负方向。
- 报告增加 v10 三项实际触发次数。

### 5. `run_strategy_ab.py`

- 每条 A/B 腿现在分别保存 report、repro、equity、curve、log，不再只留下两份汇总报告而覆盖逐根证据。
- LLM A/B 默认温度设为 0，可用 `--temperature` 显式覆盖。
- 对照表适配“成交动作、平仓回合”的新报告字段。

### 6. `verdict_llm_vs_baseline.py`

- 所有方案均为负收益时，不再按负 Calmar 选“冠军”；改为分别报告最高收益和最小回撤。
- 删除固定“每窗约120次 API”的过时描述，改为调用量约等于实际回放根数。
- 单次 LLM 结果只标记为探索性证据，要求重复运行并报告离散度。

### 7. 新增 `_probe_v14.py`

- 覆盖空仓 funding 断点、负资金费率方向、无价格状态保存、未闭合K线过滤。

## 明确未修改

- **没有接入 Binance 历史 funding 数据**：当前仍使用配置中的固定 `FUNDING_RATE_PER_8H`；本轮只修正账本时间范围、方向和计费名义额。
- **没有实现 live 的精确 `next_open` 撮合**：live 目前是“闭合K线生成信号 + 当前可执行价成交”，不会倒填历史收盘/开盘，但不等同于交易所下一根开盘瞬间成交。
- **没有把 v10 接入 live/paper 状态机**：v10 仍以回测验证为主。
- **没有修改 v10 的 EMA50、RL1、cool20、RL2 参数或增加 regime gate**。
- **没有把 `cool20` 换算成真实时间**；它仍表示 20 根K线，日线和4小时线对应的实际时长不同。
- **没有接入多次重复 A/B 的自动汇总**：目前只是降低温度并完整归档每条腿；统计重复实验仍是后续工作。

- **没有初始化 Git 仓库**，也没有修改 API 密钥、`.env` 或交易标的/仓位/杠杆参数。
